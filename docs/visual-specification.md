# Visual Specification

## Desktop

- The runtime theme catalog contains exactly `KDE_Classic` followed by `Redmond`; a fresh or legacy preference defaults to `KDE_Classic`. Standard push buttons use a compact raised light-to-gray bevel in KDE_Classic; application menubars use a light top-to-gray bottom gradient; Kicker reverses that direction from gray top to light bottom. Active titlebars use deeper KDE blue and inactive titlebars use lighter gray.
- Redmond keeps the same square geometry, bevel interaction, content semantics, font, wallpaper, icons, and `1.4` scale, but uses solid `#c0c0c0` neutral application chrome and buttons, a horizontal dark-blue-to-light-blue active title, stronger light/dark raised bevels, dark separators, and blue/navy selected application-menu rows. White/inset document, editor, terminal, file-list, tree, preview, and calendar content surfaces remain distinct. Kicker is fixed KDE_Classic shell chrome and does not change when Redmond is applied: its gray-to-white panel, flat launchers, task buttons, Pager, Clipboard, Clock, panel bevels, and gold K Menu selection remain unchanged. Desktop/Kicker/Clock context selections remain blue.
- Genuine application chrome uses one shared light-top-to-gray-bottom `KDE_Classic` surface: Konqueror's menubar, toolbar, and Location container, KWrite's menubar and toolbar, KCalc/Konsole/Control Center menubars, and the Blog action header. Address inputs, editors, published content, and other document surfaces remain white/inset. KDE_Classic window captions use a compact gray control cluster with larger raised buttons, bold black glyphs, a filled-square Minimize, an outlined-square Maximize, and a black X Close; pressing a control is visibly sunken while disabled capability remains subdued. Redmond retains its existing caption presentation and all titlebar geometry/capability behavior remains unchanged.
- Kicker launcher and Clipboard applet controls are flat and integrated into the Kicker surface while idle; pointer/keyboard press and existing active states use the KDE sunken bevel. Their hit targets and geometry remain unchanged.
- The KDE_Classic Kicker face transitions from gray to white through roughly the upper two-thirds, then stays solid white through the lower third. The Clipboard applet keeps its fixed `28 x 36` box and responsive right-side placement while its glyph uses the larger compact `21px` presentation size; the Clock, task area, Kicker height, and global `1.4` scale do not move.
- Theme Manager is a Control Center leaf beside Background. Its draft list is ordered KDE_Classic then Redmond; selecting a row does not change the applied desktop until Apply. Reset restores the applied theme and Defaults drafts KDE_Classic. Runtime switching changes the root semantic theme attribute live without remounting windows, changing geometry, or changing application state; the existing preference persistence record stores the applied theme id.

- The desktop root fills `100vw` by `100dvh`; the configured UI scale remains `1.4`, while the mounted shell's browser-applied CSS zoom is the effective scale used to publish logical viewport and work-area dimensions, with browser page zoom kept outside the application model.
- The 1024 x 768 viewport is the visual baseline.
- The bottom `46px` is reserved for the Kicker panel.
- The background uses original CSS blue tones inspired by early KDE 3 wallpapers, without embedding reference screenshots.
- KDE Control Center provides a small fixed preset set for the desktop workspace background. `KDE Classic` preserves the existing blue desktop exactly; Deep Blue, Teal, Slate, and Black affect only the workspace after Apply.
- Browser scrollbars must not appear.

## Icons

- Desktop icons are arranged vertically on the left in a single grid column.
- The icon cell is about `94px` wide and at least `78px` tall, with `48px` artwork and compact text.
- Grid rows are tall enough for two-line labels without overlapping the next icon.
- Labels are white with a dark pixel-like shadow.
- Icon definitions may provide visual-only `labelLines`; `label` remains the accessible name.
- Only two desktop icons are visible: Trash first and My Computer second. Home, CD/DVD-ROM Device, and Floppy Device have no desktop icon.
- Each visual label line is centered and uses `white-space: nowrap`.
- Trash has empty and full original SVG states. The icon exposes `data-trash-state="empty"` or `data-trash-state="full"` and keeps the label `Trash`.
- My Computer uses a compact original classic monitor/system SVG with the one-line label `My Computer`; it is not openSUSE-branded artwork.
- Desktop icons sit above the background and below the application Window Layer.
- Single click selects one icon; double click, Enter, and Space activate Trash or My Computer.
- Selected icons use a square KDE selection-blue rectangle and white text.
- Focus-visible uses a classic `1px` dotted outline.
- No rounded corners, animation, modern glow, icon scaling, multi-select frame, or drag affordance is used.
- When the global Show desktop icons preference is off, the entire desktop icon layer is absent. The Kicker, K menu, QuickLaunch, taskbar, and pager retain their normal appearance.

## Windows

- Window frames use square KDE 3 style beveled borders.
- Active title bars use a blue gradient and white title text.
- Title bar height is `22px`.
- KDE_Classic window controls form a full-height gray cluster containing `17px` raised squares with a visible one-pixel outer depth ring inside the unchanged `22px` titlebar. The Restore state uses two offset black window outlines; Minimize uses a filled black square, Maximize an outlined black square, and Close a bold black X. Press changes the bevel to sunken. In maximized presentation the KDE_Classic cluster meets the titlebar content right edge; the normal-window inset remains unchanged. Redmond explicitly retains its existing `16px` controls, spacing, and Restore glyph.
- Maximized windows keep the KDE 3 outer frame and fill the work area above the Kicker. Window bounds include the complete outer frame; edge-anchored rendering keeps the right and bottom borders inside that WorkArea at fractional UI-scale viewport widths.
- Konqueror's first-created normal window uses its configured preferred height and is capped to about `72%` of the current work area height.
- The first top-level window for every application on a virtual desktop is centered in the usable desktop area above the Kicker, using that application's resolved initial size. A second or later window of the same application cascades from this center; different applications intentionally have independent centered origins and may overlap.
- The maximize button shows a single-window glyph in normal state and a stacked restore glyph in maximized state.
- The close button keeps the classic gray KDE 3 style, not a modern red close button.
- The titlebar application icon is a `16px` window menu button. It keeps the titlebar height unchanged and uses an inset state while the menu is open. Konqueror titlebars use the same per-window semantic base icon as their Taskbar entries: Start Page and file previews use Konqueror; Home, Documents, Downloads, Music, Pictures, Folder, Trash, and My Computer follow the current location. Active/inactive titlebar state does not change this base icon, and QuickLaunch open/closed variants remain separate.
- Normal windows may be dragged partially left or right off-screen while a usable titlebar strip remains visible. They may also extend below the viewport, with their body passing behind the Kicker; Kicker always remains visibly above the normal WindowFrame.
- A normal titlebar cannot be dragged above the screen top, so a window stays recoverable. New windows still start inside the work area, and maximized windows still end at the Kicker top edge.
- Normal windows may resize beyond the right and bottom screen edges; their body may pass behind Kicker while Kicker remains above it. West resize may place the left edge partially off-screen while retaining the same draggable titlebar recovery strip, and north resize still stops at the screen top.
- In the logical mobile layout, normal windows instead remain fully inside the Kicker-free Work Area with a `4px` breathing margin on every edge. Their initial placement, cascade, drag, and resize use the same contained rectangle; maximized windows fill the exact Work Area. Switching between desktop and mobile preserves each mode's normal and maximize-restore geometry, and expanding the mobile Work Area does not automatically enlarge an existing normal window.
- There is no edge snapping, tiling, magnetic behavior, browser scrollbar, window-position persistence, or modern resize affordance.
- Window borders, inset shadows, and resize handles must remain below the Kicker layer.
- Normal resizable windows expose transparent resize hit areas on all four edges and four corners.
- Edge hit areas are `5px`; corner hit areas are `8px` by `8px`.
- Resize handles do not draw modern visible control points, colored outlines, shadows, or animations.
- Cursor mapping is `n/s -> ns-resize`, `e/w -> ew-resize`, `ne/sw -> nesw-resize`, and `nw/se -> nwse-resize`.
- Maximized windows do not expose resize handles or resize cursors.

## Window Menu

- The window menu is a compact KDE 3 style system menu opened from the titlebar icon.
- Transient menus use the shell popup layer above both ordinary application windows and Kicker; the normal WindowFrame remains below Kicker.
- The menu width is about `218px`.
- Menu items are `22px` tall with `16px` operation icons.
- The outer frame uses square KDE 3 beveled borders and a hard `1-2px` shadow.
- Active hover and keyboard rows use `--kde-menu-selection` with white text.
- There are no Move or Resize rows in the system menu; capability-disabled Minimize or Maximize rows use `--kde-disabled-text`, subdued icons, and no action.
- Separators use the recessed dark/light pair.
- The exact system-menu order is `To Desktop`, separator, `Minimize`, `Maximize`, separator, `Close`. `To Desktop` opens a right-side cascading submenu with about `1px` overlap and one row for each configured desktop.
- Desktop submenu rows use a small classic radio-style mark for the window's current desktop.
- The submenu uses `menuitemradio` semantics but no modern pill, check animation, or colored badge.
- The titlebar application icon opens the system menu on the left; a titlebar right-click opens the same menu at the pointer after activating an inactive target. Right-clicking a titlebar control suppresses the native browser menu and opens no system menu.
- Window menus have no rounded corners, animation, blur, glass, or modern large shadow.
- Phase 5.19 only prepares internal window-instance identity. Production visuals remain unchanged: Taskbar does not yet show multiple Konqueror instances, and there are no New Window commands or caption suffixes.

## Konqueror

- A supported active Media tab inserts a `Player` menubar item between `Bookmarks` and `Tools`. Its exact rows are `Play`, `Pause`, `Stop`, `Next`, and `Previous`, with no separator or extra command. The menu is absent for directories, images, documents, and web views.
- The client-area Media strip keeps the exact transport order `Previous`, `Play`, `Pause`, `Stop`, `Next`, followed by the existing seek/time/volume/mute controls. Previous and Next stay within direct media siblings in the current visible Konqueror directory sort order, stop at the first/last item, use normal Konqueror history, and open the next file paused without autoplay.

- The default Documents baseline presents `Welcome.md` as a normal Markdown document and `Notes.txt` as a normal text document. Neither is visually or behaviorally protected: their standard runtime Edit, Rename, Move, Copy, Trash, Restore, and permanent-delete paths use the ordinary VFS controls, while a refresh restores the committed baseline. The rename keeps Welcome's stable VFS identity and does not add a special icon, row treatment, or publication surface.

Help is a compact two-row menu: `About Konqueror`, then `About KDE`, with no separator. Both entries open independent normal Runtime windows with ordinary title bars and task buttons, so they never disable or visually cover the originating Konqueror window. About Konqueror uses the Konqueror icon; About KDE uses the existing About icon.

- Konqueror keeps the classic KDE 3 application layout on desktop: menu bar, navigation toolbar, Location bar, an internal tab bar only when multiple tabs exist, content area, and status bar. In mobile layout the persistent application menubar is hidden with no empty row; the compact toolbar keeps `Up`, `Back`, `Forward`, `Home`, `Reload`, and `Stop` on the left, then a flexible gap and the New Konqueror Window icon on the right. The Location bar remains a separate row.
- The Bookmarks root orders `Add Bookmark` (`Ctrl+B`), `Bookmark Tabs as Folder...`, `Edit Bookmarks`, and `New Bookmark Folder...`. When the saved root has children, one separator precedes its recursive mixed Bookmark/Folder order; existing KDE-style Bookmark and Folder icons share a fixed leading column, Folder rows retain their submenu arrow, and Bookmark leaves have neither arrow nor shortcut. Long labels truncate inside the existing compact menu width so neither the shortcut column nor arrow column moves. Each non-empty Folder submenu shows its mixed children, a separator, then its existing folder-targeted commands; empty folders have no separator. Opening a Bookmark closes the menu and navigates only the invoking Konqueror's active tab through the normal Location path. There is no Bookmark context menu, Konqueror toolbar, favicon fetching, or layout change in this surface.
- `Edit Bookmarks` opens one normal KDE-style Bookmark Editor singleton; Folder submenus do not repeat it. The compact utility window uses an icon toolbar, a labelled Search field, and a dense mixed-order expandable tree with Bookmark, Location, and Comment columns followed by an inset details panel. Folder, Bookmark, and synthetic-root icons use existing KDE assets; selection remains rectangular. Bookmark details permit Name, Location, and Comment edits while First viewed, Viewed last, and Times visited remain read-only with `—` for absent metadata; Folder details expose only Name and the synthetic root stays read-only. Search, no-result state, selection, and expansion are local UI state. Disabled commands remain visibly subdued, and the editor adds no Konqueror toolbar, context menu, favicon, or layout changes.
- Blog article titles with an authored current publication slug retain the existing underlined KDE link treatment as native `#/blog/<slug>` anchors; historical aliases are not displayed. v4 publications remain ordinary node-backed title actions. Article Reader shows a compact `Permalink:` row only for a live current slugged publication. An old hash alias silently becomes the current hash through History API replacement before opening the same normal Article Reader instance; it adds no browser-style chrome, status field, route indicator, alias badge, or pathname routing UI.
- A live Article Reader ends with a compact recessed Previous/Next footer below the document body. Each side holds its current catalog-adjacent article title in the existing link treatment, while unavailable boundary sides remain subdued fixed slots. Slugged targets are canonical links; slugless v4 targets retain the same visual control as a node-backed action. Activating a target opens another Article Reader window and leaves the current Reader visible; there is no in-place document replacement, wrap-around, animation, or Reader-local history UI.
- The functional Konqueror menubar is compact `Location`, `Edit`, `View`, `Go`, `Bookmarks`, `Tools`, `Settings`, `Window`, and `Help`. Location is `New Window`, `New Tab`, separator, `Print`, separator, `Quit`; New Tab opens an active blank internal tab. Tools is exactly `Open Terminal`, `Find File...`; Open Terminal is subdued whenever the active tab is not an ordinary filesystem directory, while Find File remains a normal KFind launcher. Window is exactly `New Tab`, `Duplicate Current Tab`, `Detach Current Tab`, `Close Current Tab`, with the latter two subdued for a single-tab window. A New Window stays an independent Konqueror window; Duplicate copies only the current target into a fresh tab history, while Detach moves the active session to a new Konqueror window. Edit is `Undo`, `Cut`, `Copy`, `Paste`, `Rename`, `Move to Trash`, `Delete`, `Copy Files`, `Move Files`, `Create New`, and `Properties`. Undo is a normal compact KDE3 row: it is subdued when there is no shared reversible file operation or a local dialog blocks commands, and enabled in every Konqueror window after a successful reversible file batch. It has no Redo companion, keyboard shortcut, toast, history panel, or layout change. Copy Files and Move Files are enabled only for an eligible active-tab filesystem selection. They open an owner-local compact `Copy Files` or `Move Files` destination dialog with a focused `Destination folder:` absolute VFS-path field, initialized to the current folder path, plus classic OK/Cancel controls. The dialog accepts existing ordinary VFS directories only; relative paths, `file:` URLs, virtual locations, files, missing paths, and Trash are rejected inline. It has no Browse button, host filesystem picker, navigation, status indicator, or geometry change. Create New contains `Folder`, separator, and `Text File`. View contains View Mode (`Tree View`, `Icon View`), separator, and Sort (`By Name`, `By Size`, `By Type`, `By Date`, separator, `Descending`). The checked sort key is exclusive, while Descending is an independent checkbox. It opens one square, light-gray KDE3 dropdown at a time, with bevel borders, compact rows, disabled text, and a narrow check column. Nested panels use the same owner-scoped pre-paint placement and left-flip/clamp rules. Opening, switching, outside dismissal, or Escape never alters directory selection or clipboard state.
- The navigation toolbar is a fixed-height, icon-only KDE 3.0 chrome surface. Its resolved content profile changes the visible inventory without moving the Location bar or content viewport: Resource Manager is used for folders, Trash, and My Computer; Web is used for the Start Page, local KHTML, and HTTPS content; Document is used for Embedded Text and Markdown previews; Image is used for local MIME-recognized image previews; Media is used for supported local MIME-recognized audio/video assets.
- Toolbar and Location occupy the two fixed owner-local dock slots below the Menu Bar. Without a saved preference, new Konqueror windows show Toolbar above Location; dragging either classic striped left grip can exchange them to Location above Toolbar. A completed exchange becomes the default for later Konqueror windows and browser refresh recreation, while already-open windows retain their own order. The bands never float, remain inside their Konqueror window, and snap back when released outside the dock area.
- The final Konqueror content modes are Resource, Document, local KHTML, external HTTPS, the Start Page, `about:blank`, Image, and MIME-recognized Media. Profiles decide which buttons are visible; the resolved content mode decides whether those controls are active, so the shared Web profile does not make local, Start Page, Blank, external HTTPS, Image, and Media capabilities interchangeable. Blank is a completely empty content surface.
- Every profile keeps the compact `Up, Back, Forward, Home, Reload, Stop | Cut, Copy, Paste | Print | Zoom In, Zoom Out` sequence. Resource Manager then shows Icon View and Tree View; Web then shows Security; Document and Media end after their common groups, with Media retaining the visible but disabled Print action. Media has no image zoom, rotation, or custom playback toolbar controls. Classic recessed dividers separate these groups, and a KDE icon remains at the far right as New Konqueror Window.
- Icon View and Tree View are mutually exclusive and share one state with the View menu. They are active for ordinary folders and Trash; My Computer is a dedicated resource-profile page and keeps those renderer-specific controls subdued. An explicit Tree/Icon choice becomes the silent default for future Konqueror windows and browser-refresh recreation; open windows retain their own mode. Resource Zoom In/Out is active only for those resource renderers: Tree and Icon retain separate local levels, while an explicit change becomes that mode's default for future windows and browser-refresh recreation. Start Page, local KHTML, Embedded Text, and Markdown enable their own Zoom and Print controls; at their minimum/maximum level the relevant Zoom Out/Zoom In button is subdued. External HTTPS has Security and parent-side iframe viewport Zoom enabled while Cut/Copy/Paste and Print remain disabled. Image View follows the classic image sequence: navigation, Cut/Copy/Paste, Print, Previous Image, Next Image, Zoom In, a compact Fit/Zoom selector, Zoom Out, and Rotate Right. Its selector is Fit to Window by default and offers Fit to Width, Fit to Height, 50%, 100%, and 200%; image leaves have the gray preview viewport, no external browser frame, and no added status or geometry. The early KDE3.0 toolbar intentionally has no Download control; later KDE3.x KGet-oriented variants are outside the visual target. Resource clipboard buttons retain their existing availability, while non-resource content does not pretend to operate on remote or read-only selections.
- Resource Tree/Icon, Document, Internal Web, and External HTTPS keep separate per-window presentation values. Returning through mixed Back/Forward history restores the relevant value without resizing Konqueror chrome or changing the window geometry.
- In the Resource profile, Up is active at `/home/user` and `/home`, following the visible VFS hierarchy to `/home` and then `/`; it is subdued only at the real `/` root. Home remains the separate shortcut to `/home/user`.
- Disabled toolbar buttons use subdued contrast and keep their square layout footprint.
- While a text draft is open, navigation buttons and the Location input show disabled KDE 3 styling.
- Location uses a compact editable text input with an inset border and a small Go button. Enter and Go submit the same visible draft through the same resolver, independent of the current view. It displays the live VFS, protocol, or canonical HTTPS presentation, accepts absolute VFS paths plus the allow-listed `about:konqueror`, `sysinfo:/`, and `trash:/` virtual locations, and never changes the browser URL. HTTPS pages fill only Konqueror's content view while its menu, toolbar, Location bar, and status bar remain visible. A remote site's own frame policy may prevent embedding; the application does not claim an exact X-Frame-Options or CSP reason. A generic Konqueror Start Page launch intentionally leaves the Location field empty and gives that input native keyboard focus without selecting text; a Start Page reached by typing `about:konqueror` visibly retains that text and returns keyboard ownership to its scroll surface.
- `about:konqueror` is the KDE3-style Conquer your Desktop! Start Page: a blue Konqueror hero with the compact tagline, explanatory line, and two-column Starting Points. Home Folder, Storage Media, Trash, and Settings are active classic links; Network Folders and Applications are visibly unavailable. Home Folder, including Kicker Home, targets `/home/user`. The grid collapses to one column in a narrow Konqueror window without horizontal overflow, and the page is a focusable native scroll surface with no intrusive outline.
- Trash is presented as `trash:/` with the caption `Trash - Konqueror`; nested Trash folders use their current folder basename caption and retain the compact `trash:/relative/path` Location display. The real virtual backend path is not normally exposed in Konqueror, and the protocol root has a subdued disabled Up button.
- My Computer is a dedicated Konqueror page at `sysinfo:/`, with title `My Computer - Konqueror` and status `Page loaded.`. It has a compact blue classic header, Common Folders, Disk Information, Network Status, OS Information, CPU Information, Display Info, and Memory Information sections. The desktop-width layout is two columns and collapses to one narrow column without horizontal overflow.
- The page uses compact square framed sections and blue heading strips, not modern cards or openSUSE green branding. Disk data is explicitly virtual in-memory VFS information; unavailable browser information is shown as text rather than fabricated hardware values. After My Computer activation, its unobtrusive focusable scroll surface owns native Arrow, Page Up/Down, Home, and End scrolling; focused inputs, menus, toolbar buttons, and Common Folder links retain their normal browser focus behavior.
- Tree, Icon, Zoom, Sort, and file-operation controls are disabled while this page is shown. Common Folder links return to the ordinary VFS directory presentation, where the existing directory keyboard focus is restored.
- Tree View is a detailed Resource hierarchy rooted at the current Location, with Name, Size, Type, and Modified columns. The root itself is not shown and direct children begin collapsed. Every normal folder, including an empty one, has a compact square CSS-drawn plus/minus control; an expanded empty folder simply has no child rows. A fixed gutter inside the Name column renders continuous 1px T-junctions, elbows, and ancestor continuations without fabricated root or spacer rows. Tree selection paints only the tight square Name label; ordinary and context pointer ownership remains full-row, while marquee intersects the rendered Name-label rectangle only.
- Tree headers are compact clickable KDE-style header buttons. The active column shows a simple static `▲` or `▼` indicator and matching `aria-sort` state.
- Icon View uses the same sorted entries in a compact responsive file-manager grid with existing folder/text icons and two-line filename labels. Selected icon+label regions use the existing square KDE selection blue, not card styling or thumbnails. Resource Zoom uses four discrete levels: Icon View changes icon and cell geometry together, while Tree View changes row and node-icon geometry without scaling its header or columns. Tree and Icon each remember their own level for the current Konqueror window, and explicit Zoom In/Out remembers that mode's level as the default for future Konqueror windows and after reload; the default remains the current normal KDE3 density. Switching views restores that view's own zoom.
- Modified and Trash deleted timestamps use the browser/system local timezone while VFS stores the underlying ISO UTC instant unchanged.
- Tree rows are compact at about `22px` high and use `16px` node icons at normal zoom. Zoom ranges from `20px/12px` rows/icons to `32px/24px`; the fixed Tree header does not zoom.
- Icon selection uses KDE selection blue with white text; Tree selection uses the same palette only on its Name label. Tree and Icon share one runtime selection: collapsing a Tree branch or changing to Icon View removes selected descendants that are no longer visible. The visible Tree order also drives Shift range, marquee result order, ordinary Up/Down navigation, Context Menu group snapshots, Copy/Cut operation-root ordering, and Open in New Window launch order.
- Focus-visible uses a classic `1px` dotted outline.
- Empty folders show only the small text `This folder is empty.`
- Text files use a Konqueror Preview Component. Embedded Advanced Text Editor is the compact read-only source viewer: monospace `<pre>`, preserved whitespace, selectable text, vertical scrolling, and horizontal scrolling for long lines. It may show the compact file header with file name, MIME type, size, and modified time.
- HTML/HTM files default to KHTML: a light document canvas inside the existing Konqueror content area with compact classic headings, paragraphs, lists, tables, blockquotes, code, and inert underlined links. Explicit HTML5 `video`/`audio` blocks use native controls and the same source-relative VFS asset boundary as document images; missing or unsafe sources retain fallback text and do not fetch arbitrary resources. Autoplay, event handlers, custom playback controls, and codec/transcoding behavior are absent. Video and audio stay contained within the document scroll surface at narrow widths without cropping.
- Supported audio/video files remain ordinary VFS asset-url files and open in the current Konqueror tab as a black responsive Media stage. Audio and video use one shared compact KDE3 transport strip below the stage, begin paused, and never autoplay; the native `controls` surface is not rendered. The strip provides Play/Pause, Stop, finite-duration Seek, Volume, Mute, and `mm:ss`/`h:mm:ss` labels, while unknown duration remains `--:--`. Video uses contain-style fitting and audio keeps an otherwise quiet black stage. Leaving the tab or file pauses and cleans up the native element, while window minimize and virtual-desktop changes do not add application-specific playback policy. Reload and Stop reset the current media entry without changing global window history; waiting, rejected-play, invalid, or unsupported media remains a controlled preview state.
- Remote HTTPS pages use their own restricted embedded web view; they are distinct from local KHTML and Markdown previews, which remain inert and network-free.
- Markdown files default to Markdown Renderer: the same light document canvas with compact headings, paragraphs, lists, quotes, inline/fenced code, rules, inert links, image placeholders, and explicit HTML5 media blocks. Ordinary Markdown media links remain links, while explicit video/audio uses native controls, fallback text, and responsive contained sizing. Selecting Embedded Advanced Text Editor displays the literal Markdown source instead.
- Internal Web content (Start Page/KHTML), Document content (Embedded Text/Markdown), and External HTTPS each use independent per-instance toolbar Zoom memory: `75%, 90%, 100%, 110%, 125%, 150%`, defaulting to `100%`. External Zoom is a parent-side scaled iframe viewport with inverse dimensions, not remote page or browser-engine zoom; it leaves KDE chrome unchanged and is retained through Reload and owned navigation. External HTTPS Print remains disabled.
- Printing uses the browser's native dialog and outputs only the current Start Page, safe KHTML rendering, rendered Markdown, or preformatted Text content from the clicked Konqueror window. Window position, window size, and browser screen viewport do not determine the paper layout: the document starts in the normal printable area without a screen-preview frame border and naturally flows onto later pages when long. The desktop, WindowFrame, toolbar, Location bar, status bar, and other windows are not printed; screen zoom does not dictate printer scale.
- Navigation errors, including invalid or non-directory Location input, use a small classic warning strip inside the content area; the current directory remains visible. A failed Location submission restores the current displayed address once, then the still-focused input can immediately be edited, pasted into, or replaced without another click.
- New Folder, New Text File, Rename, and item-menu Create Folder use a Konqueror-internal input dialog, not a Window Manager window. Create Folder presents `Folder name:` with compact OK/Cancel controls and an initially empty focused input.
- The input dialog covers only the Konqueror client area and keeps the titlebar and window controls visible.
- Dialogs use a gray KDE panel face, square raised outer border, compact title text, inset input, and classic OK/Cancel buttons. Copy Files and Move Files reuse this exact dialog treatment; they copy or move selected files, folders, and Links directly into the entered folder using the established collision and recursive-safety behavior, without navigating to the destination.
- Dialog errors appear inline inside the dialog with `role="alert"` and a restrained warning background.
- Properties is a Konqueror-internal General metadata dialog with the selected folder/file icon, read-only Name, Type, Location, Size, Created, Modified, and Full path labels, plus one classic OK button. It follows live node metadata through Rename, Move, Save, Trash, and Restore. A permanently deleted backing node shows a compact unavailable message until OK or Escape closes the dialog.
- Properties uses the same gray square KDE3 dialog treatment, browser-local Created/Modified presentation, and directory `-` size placeholder as the directory list. It is not a permissions editor and contains no editable controls.
- Tree rows, Icon View items, and directory background support a compact KDE3 context menu. The popup uses a square gray beveled frame, narrow text rows, recessed separators, classic blue hover selection, subdued disabled text, and no animation, blur, rounded corners, or modern popover styling.
- Tree View uses a fixed hierarchy gutter inside the Name column. The Name header leads directly into the first actual top-level branch: each non-final top-level row uses a T-junction and the final row uses an elbow, with no fabricated root, root stem, or blank connector row. Per-row thin classic gray 1px continuation lines form the same T-junctions and elbows for nested siblings; branch segments stretch across the full Tree row while the compact expander remains independently centered, and adjacent row segments overlap by one pixel to remain continuous across row boundaries. Tree body rows have no horizontal separators, while the header retains its classic border. The gutter uses CSS geometry rather than text branch glyphs. Every row reserves the same 16px expander hit slot and post-slot icon gap: directories use a compact centered 9px square CSS-drawn plus/minus control, files leave the slot visibly empty, and empty directories still show the control while expanded empty directories simply have no child rows. A selected Tree item keeps its branch, expander, icon, Name-cell remainder, and Size/Type/Modified presentation normal; only the visible Name label receives a tight square KDE selection rectangle. Tree rows remain full-width ordinary pointer and context-menu targets, while Tree marquee selection intersects only the rendered Name label rectangle; Icon View marquee keeps its existing item-cell contract. Unmodified Right expands a collapsed directory or enters the first visible direct child of an expanded directory; unmodified Left collapses an expanded directory or returns to its visible parent. These keys neither open items nor navigate Location/history.
- Konqueror context menus and their Preview in / Open with / Actions submenus may extend beyond the owning WindowFrame's right or bottom edge and may cover Kicker, like desktop application menus. A result has at most one compact, whitespace-bounded body snippet anchored at the earliest body match, with ellipses only when clipped. Metadata-only results do not gain filler snippets. Raw markup, URLs/resources, image alt text, HTML attributes, and non-content script/style text do not create matches or appear in snippets. Empty queries do not display all publications, and `#/blog/search` remains available to an article slug named `search`. Slugged rows use the existing native article links while slugless rows retain ordinary node-backed activation. There is no Desktop Search icon, secondary Full Text Search control, score/relevance treatment, multiple snippets, or Search-scoped Reader navigation.
## Global KDE3 UI Scale

At browser zoom 100%, the complete desktop shell uses the fixed `1.4` KDE3 presentation scale. Desktop icons, windows, titlebars, menus, Kicker applets, task buttons, popups, and Calendar enlarge together while retaining their compact proportions. A logical viewport keeps the Kicker at the visible bottom edge and keeps maximized windows above it; pointer and submenu geometry follows the same logical coordinate system. This is not an application content zoom and does not add a scale setting or status indicator.

The responsive foundation derives `mobile` versus `desktop` from the logical viewport width, using an inclusive `480px` logical boundary, and derives portrait versus landscape from actual width/height geometry (`width <= height` is portrait). CSS and JS use the same unzoomed `#root` used geometry backed by `100vw`/`100dvh`; root `ResizeObserver` plus window and visual-viewport resize events invalidate one coalesced responsive refresh. The stable desktop shell exposes these states through `data-layout-mode` and `data-orientation`. On mobile, the Kicker keeps Start, the pager, and Clock in the accepted compact presentation; managed windows use exact Work Area bounds by default, while Calendar is the sole stable-ID exception and preserves a Clock-provided compact anchor above the Kicker, with complete WorkArea containment and no automatic stretch after expansion. Desktop normal/maximized profiles remain independent, and minimized windows remain minimized. Browser zoom remains available and changes the effective CSS viewport naturally, while the internal KDE scale is applied only once. Safe-area insets are prepared through logical CSS tokens and the shared responsive hook but are not yet used to move visible desktop elements. `viewport-fit=cover` remains deferred until edge-to-edge consumption is introduced.

Rotation reflows the same mounted desktop: `390x844` presents mobile portrait, `844x390` presents the geometry-derived desktop landscape, and returning to `390x844` restores mobile presentation without resetting window identity, virtual desktop, active/z-order state, or application state. Titlebar and resize gestures that lose pointer capture or receive `pointercancel` disappear without committing a partial move or resize; completed desktop pointer-up gestures retain their existing behavior.

Mobile K Menu presentation keeps Configure Panel, KCalc, Find Files, Bookmarks, Quick Browser, and Run Command visible in their existing positions but disabled by stable semantic identity. Desktop K Menu behavior, gold selection, and Most Used ordering are unchanged; this policy does not add touch gestures or a second menu hierarchy.

## Touch Interaction Foundation

The KDE3 shell keeps its compact visual faces while making the existing controls touch-capable. Start, Pager, and Clock retain their normal single-tap actions. K Menu rows activate by tap without relying on hover; nested mobile cascades add a compact localized `Back` row, keep the gold K Menu presentation, and retain native vertical scrolling. Desktop icons select on the first touch, open on the second touch, and use the existing desktop context menu for a still-held long press. Empty desktop long press uses the existing background context menu.

Long press uses one `500ms` threshold and cancels after more than `8px` of browser client-coordinate movement, a second pointer, `pointercancel`, early release, or unmount. The resulting context action consumes the browser's follow-up click, so no duplicate activation appears. The shell does not use user-agent detection and does not globally disable touch behavior or browser pinch zoom.

In mobile layout, visible window captions keep Close enabled while Minimize and Maximize/Restore are visibly disabled and semantically inert. Desktop-layout titlebars and invisible resize handles accept touch/pen pointer gestures without changing the KDE3 frame geometry; mobile enforced-maximized windows remain fixed. App-internal touch layouts and gestures remain outside this shell foundation.

## Konqueror Mobile Layout

When the shared shell publishes `data-layout-mode="mobile"`, Konqueror keeps its KDE3 controls and state while hiding the persistent application menubar and using a compact, non-scrolling navigation toolbar. The toolbar retains only `Up`, `Back`, `Forward`, `Home`, `Reload`, `Stop`, and the right-aligned New Konqueror Window icon; the Location Bar and tabs remain separate tracks. Details retains the fixed Name/Size/Type/Modified columns inside an internal horizontal scroller; Icon View fits its existing file items into the available width. Tree hierarchy is unchanged, and dialogs, Properties, Bookmark Editor, sysinfo/about, image/text preview, and the existing audio/video player use compact stacking or contained overflow rather than a second mobile application surface.

Other first-party windows use the same shared mobile mode. KWrite prioritizes the native editor surface and keeps only Open, Save, Undo, and Redo in its compact toolbar; Konsole keeps its native terminal selection and scrollback; Control Center stacks navigation above the selected module; KFind preserves complete result columns inside its table scroller; Blog Tags stacks the tag list above article details; and KCalc shrinks only its mobile layout tokens, with an internal optional-column scroller when necessary. Blog, Article Reader, About, Calendar, Bookmark Editor, Configure Panel, and Configure Clock keep their existing content semantics while wrapping long text and containing dialogs. Desktop geometry, menubar policy, K Menu availability, themes, and application state remain unchanged.

Touching a resource selects it first and opens the same selected resource on a second tap. A still-held resource or empty-view press opens the existing context menu through the shared long-press boundary; movement cancels activation and does not produce a ghost click. K Menu Bookmarks remains disabled on mobile; the persistent Konqueror Bookmarks menubar is hidden, but its desktop menu model, shortcuts, and data remain intact. Desktop presentation, VFS/content visuals, navigation semantics, media controls, and window geometry remain unchanged.
## Published Markdown Presentation

  Published Markdown may carry a YAML front matter block containing title and the existing publication fields. The block is authoring metadata, not visible article content: Blog, Article Reader, Konqueror Markdown preview, and safe search consume the parsed body only. A front-matter title supplies the file's friendly VFS display label while the filename/path and stable identity remain unchanged.

  Publication routes use the explicit authored slug; titles do not silently rename routes. Tags keep their authored order and case, summaries and exact UTC publication dates remain unchanged, and VFS created/modified timestamps stay in the sidecar. Legacy sidecar-only articles remain supported during migration. Conflicting dual sources are rejected rather than visually merged.
